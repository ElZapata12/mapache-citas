# Glosario

Un término por línea. Si alguien del equipo usa una palabra de dos formas distintas, se define aquí.

## Del negocio

| Término | Significado |
| --- | --- |
| Cita | Reserva de un cliente con un barbero para un servicio, en una fecha y hora. |
| Empalme | Dos citas del mismo barbero cuyos horarios se traslapan (RN-01). |
| Hueco | Bloque libre de la agenda donde cabe un servicio. |
| Baja lógica | Marcar `activo = False` en lugar de borrar el registro. |
| Costo cobrado | Precio copiado a la cita al agendar; no cambia si el servicio cambia de precio. |

## Del proceso

| Término | Significado |
| --- | --- |
| Spec | Documento corto que dice qué hace una funcionalidad, por qué y cómo sabremos que funciona. |
| Criterio de aceptación | Condición verificable escrita como Dado / Cuando / Entonces. |
| ADR | Registro de una decisión técnica: contexto, opciones, decisión y consecuencias. |
| Sprint | Ciclo de una semana con objetivo, revisión y retrospectiva. |
| Definición de terminado | Lista que debe cumplir algo para considerarse terminado. |
| PR | Pull request: propuesta de cambio que otro integrante revisa antes de unirla a `main`. |
| Rebanada vertical | Funcionalidad completa de punta a punta (base de datos, API, pantalla y pruebas), en lugar de construir por capas. |
